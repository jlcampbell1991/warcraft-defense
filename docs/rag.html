Retrieval‑Augmented Generation (RAG)

What is RAG?

RAG combines a retrieval system (often a vector store) with a large language model to produce answers that are grounded in external documents.

Core Components

  • Retriever – fetches relevant chunks from a knowledge base.
  • Vector Store – stores document embeddings for fast similarity search.
  • LLM – generates the final response using the retrieved context.
  • Prompt Template – formats the retrieved text for the LLM.

Typical Workflow

  1. Embed documents and store them in a vector database.
  2. When a user asks a question, embed the query.
  3. Retrieve the top‑k most similar document chunks.
  4. Insert those chunks into a prompt and call the LLM.
  5. Return the LLM’s answer to the user.

How to Use It (Pseudocode)

docs = load_documents("./knowledge")
vector_store = embed_and_store(docs)

def answer(question):
    q_vec = embed(question)
    relevant = vector_store.search(q_vec, k=5)
    prompt = build_prompt(question, relevant)
    return llm.generate(prompt)

Best Practices & Tips

  • Chunk documents into 300‑500 token pieces.
  • Use a dense embedding model (e.g., OpenAI’s text‑embedding‑ada‑002).
  • Filter retrieved chunks by relevance score before prompting.
  • Keep the prompt under the model’s token limit.
  • Cache frequent queries to reduce latency.
