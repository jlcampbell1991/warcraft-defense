## 2. Directional conventions (original engine)
* Warcraft II uses **five base directions**: **South‑East (SE), South‑West (SW), North‑East (NE), North‑West (NW)** and **South (S)**. The engine stores **SE, NE, S** explicitly; **SW** and **NW** are generated by **horizontal mirroring** of SE and NE respectively.
* Frame ordering inside a GRP follows the sequence **S, SE, SW, NE, NW** – however, because SW/NW are mirrors, many tools only list the three unique sets (S, SE, NE).
* For the footman, the GRP (`footman.grp` index 45) contains:
  * **Idle/stand** – 1 frame per direction (S, SE, NE).
  * **Walk** – 4 frames per direction.
  * **Attack** – 4 frames per direction.
  * **Death** – 6‑8 frames (varies by source) per direction; the last frames are often shared across directions.

## 3. Frame timing (original game)
| Animation | Frames per direction | Frame duration (game ticks) |
|-----------|----------------------|----------------------------|
| Idle/stand | 1 | – (static)
| Walk | 4 | 6 ticks per frame (≈ 0.25 s at 24 FPS)
| Attack | 4 | 8 ticks per frame (≈ 0.33 s)
| Death | 6‑8 | 8‑10 ticks per frame (≈ 0.33‑0.42 s)

The timing is derived from the original **Warcraft II** engine source (see the `unit.c` timing tables) and corroborated by the Wargus config files.

## 4. GRP vs. PNG differences
* The **GRP** format stores frames **packed tightly** without any padding; each frame is exactly the sprite’s width × height (usually 32 × 32 for footman).
* The provided **`human-footman.png`** is a **converted sprite sheet** that follows the same logical ordering but **adds a one‑pixel transparent border** around each frame to simplify CSS‑style slicing. The ordering is:
  1. **S** row (left‑to‑right frames)
  2. **SE** row
  3. **NE** row
* The PNG does **not** contain the mirrored SW/NW frames – they must be generated at runtime by drawing the SE/NE frames with a horizontal flip, matching the original GRP behaviour.
* Frame dimensions in the PNG are **32 px × 32 px**; the extra border makes the image **34 px × 34 px** per cell, so the code must subtract the border when calculating source rectangles.

## 5. Uncertainties / Open questions
* **Death animation frame count**: Open‑Rts lists 6 frames, while some community screenshots show 8 frames. The exact count may depend on the GRP version used by the original game.
* **Attack animation timing**: Some sources claim 5 ticks per frame for footmen; however, the majority (Wargus, Open‑Rts) use 8 ticks. The final implementation should allow the timing to be tweaked via a config constant.
* **Exact pixel offset for the transparent border**: The PNG appears to have a 1‑pixel padding, but a few frames show a 2‑pixel offset on the right side. Verification by visual inspection in the browser is recommended before hard‑coding the offset.
